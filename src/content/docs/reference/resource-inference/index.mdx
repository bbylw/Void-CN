---
title: 资源推断
description: Void 会识别代码用到的 Cloudflare 资源并开通对应的绑定，手动配置只是可选项。
---

Void 在启动时扫描源文件，自动识别项目用到哪些 Cloudflare 资源。多数情况下无需任何手动配置：在代码里用某个资源，Void 就会为本地开发开通匹配的绑定。

## 识别出的绑定

| 绑定         | 类型                     | 通过导入识别                                                                                                                                             | 通过访问 env 识别                                                            |
| ------------ | ------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| `DB`         | `D1Database`             | `import { db } from "void/db"`                                                                                                                           | `env.DB` 或 `c.env.DB`                                                       |
| `KV`         | `KVNamespace`            | `import { kv } from "void/kv"`                                                                                                                           | `env.KV` 或 `c.env.KV`                                                       |
| `STORAGE`    | `R2Bucket`               | `import { storage } from "void/storage"`                                                                                                                 | `env.STORAGE` 或 `c.env.STORAGE`                                             |
| `AI`         | `Ai`                     | `import { ai } from "void/ai"`                                                                                                                           | `env.AI` 或 `c.env.AI`                                                       |
| `SANDBOX`    | Managed Sandbox 能力     | `import { getSandbox } from "void/sandbox"`                                                                                                              | `getSandbox()`；原生 Cloudflare 环境还会暴露 `env.SANDBOX` / `c.env.SANDBOX` |
| Auth         | 无                       | `import { ... } from "void/auth"`，或从 `void/client` / `void/client/react` / `void/client/vue` / `void/client/svelte` / `void/client/solid` 导入 `auth` | 无                                                                           |
| `QUEUE_*`    | `Queue`                  | `import { queues } from "void/queues"`                                                                                                                   | `env.QUEUE_*`                                                                |
| `VOID_LIVE`  | `DurableObjectNamespace` | `import { defineLiveStream } from "void/live"`                                                                                                           | 不适用                                                                       |
| 由文件名推导 | `DurableObjectNamespace` | `durable-objects/` 中默认导出 `defineDurableState()` 的模块                                                                                              | 不适用                                                                       |

从 `void/client` 或框架专用的客户端子路径（例如 `void/client/react`）导入 `auth` 这个 specifier 时，同样会触发 Auth 识别（只导入 `fetch` 则不会）。

静态的下标访问，例如 `c.env['KV']`，以及解构出的属性，例如 `const { DB, KV: cache } = c.env`，也会被识别。对于在运行时才决定键名的情况，请使用[显式绑定覆盖](#显式绑定覆盖)。

Durable state 由 `durable-objects/` 中的文件推导。例如 `durable-objects/shopping-cart.ts` 会创建 `SHOPPING_CART` 绑定，导出 `ShoppingCartDurableObject`，并记录它的迁移。见 [Durable State](/docs/durable-state)。

## 扫描的目录

### 标准模式

原生 Void 应用默认扫描这些目录。配置了 [`sourceDir`](/docs/config) 时，Void 改为扫描那棵源码树：

| 目录          | 内容                               |
| ------------- | ---------------------------------- |
| `routes/`     | API 路由处理器                     |
| `middleware/` | Hono 中间件                        |
| `queues/`     | 队列消费者                         |
| `pages/`      | 页面组件与配套的 `.server.ts` 文件 |
| `crons/`      | 定时任务处理器                     |
| `email/`      | 收件邮件处理器                     |
| `src/`        | 应用源码                           |

### 框架模式

对于[受支持的元框架](/docs/frameworks)，Void 扫描这些目录：

| 目录      | 内容            |
| --------- | --------------- |
| `src/`    | 应用源码        |
| `app/`    | 框架的 app 目录 |
| `routes/` | 框架路由        |
| `server/` | 服务端代码      |
| `pages/`  | 框架页面        |
| `crons/`  | 定时任务处理器  |
| `queues/` | 队列消费者      |

框架识别依据 `package.json` 的 dependencies 与 dev dependencies。请在框架的 Vite 配置中加入 `voidPlugin()`，以便开发期间也能进行推断。各框架的配置方式见对应的集成指南。

### 始终扫描

不论哪种模式，这些位置总会被检查：

- **SSR 入口**，例如 `src/main.ssr.ts`，用于在渲染期间访问绑定的 SSR 应用
- **应用源码**，即 `src/` 或你配置的 `sourceDir`，包括资源导入与 auth 导入
- **`durable-objects/`**，在原生 Void 应用中会扫描其中带类型的 Durable Object state 模块

## 自定义扫描目录

如果项目把代码组织在非标准的目录里，你可以覆盖被扫描的目录列表：

```json
{
  "inference": {
    "scanDirs": ["src", "lib", "workers"]
  }
}
```

路径相对于项目根目录。设置 `inference.scanDirs` 后，它会完全替换默认目录。SSR 入口与应用源码的扫描仍然执行。

## 显式绑定覆盖

当推断结果与你的实际配置不符时，用 [`inference.bindings`](/docs/config) 启用、禁用或重命名某个绑定。它只覆盖你点名的那些绑定，其余仍然走推断。

## 文件类型

推断会扫描 `.ts`、`.tsx`、`.mts`、`.js`、`.jsx`、`.mjs` 以及 Astro 的 frontmatter。请把服务端资源导入写在这些文件里，或页面的 `.server.ts` 伴生文件中；Vue 与 Svelte 组件文件不会被直接扫描。
