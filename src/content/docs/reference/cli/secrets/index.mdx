## `void secret list`

```sh
void secret list [--project <name>]
```

列出已保存目标上的生产环境密钥名。密钥值永不打印。直连 Cloudflare 的目标查询 `void.config.ts` 中命名的 Worker；`--project` 仅托管项目可用。

## `void secret put`

```sh
void secret put <name> [--project <name>]
void secret put <name=value> [--project <name>]
```

值的输入方式：

- 内联：`void secret put API_KEY=abcd`
- 提示输入（TTY）：`void secret put API_KEY`（掩码输入）
- stdin：`echo -n "abcd" | void secret put API_KEY`

在直连 Cloudflare 的目标上，该值以加密的 Worker secret 形式存储。

## `void secret sync`

```sh
void secret sync <file> [--project <name>] [--yes]
```

从存放在项目目录之外的 dotenv 文件上传服务端的生产值。只包含 `env.ts` 中声明过的键；不要放本地开发凭据和公开的 `VITE_*` 值。

```sh
void secret sync /secure/path/production.env
```

在脚本与 CI 中传 `--yes` 跳过确认。

文件里没有、但远端已存在的 secret 会保留。每一项都必须是 `env.ts` 中声明的服务端键，且其值必须通过校验。

## `void secret delete`

```sh
void secret delete <name> [--project <name>]
```

secret 系列命令使用 `.void/project.json` 中保存的平台。托管项目的解析顺序与 deploy 一致（`--project`、环境变量、已关联项目）。直连 Cloudflare 的目标会拒绝 `--project`，并使用被固定的根 Cloudflare 配置。

在托管项目上，当有部署或回滚正在进行时，写入与删除 secret 会返回一个可重试的冲突。请等该操作结束后重试；被拒绝的操作不会改动已存储的 secret。

## Env Schema

### `void env check`

```sh
void env check [--remote]
```

不带 `--remote` 时，校验 `.env` 加上 shell 环境，用于本地开发。带 `--remote` 时，校验构建 shell 中的客户端值以及远端 server secret 的名称。如果缺少必需的键，或可读的值不合法，则以非零状态退出。

### `void env types`

```sh
void env types
```

从 `env.ts` 重新生成 `.void/env.d.ts`。通常开发服务器启动与 HMR 时会自动完成；在刚克隆完仓库之后，或在非开发场景下刷新过期类型时，使用这条命令。

<Callout type="tip" title="部署时的校验">
  `void deploy` 会自动执行同一套 schema 校验（连同远端 secret），只要有必需键缺失就拒绝上传——部署时无需单独调用 `env check`。
</Callout>

完整指南见[环境变量](/docs/env-vars)。
