为这个平台在密码管理器里保留一条记录。安装器要的时候就把保存的值粘贴进去；大多数都不需要 shell 环境变量。

| 凭据                                     | 由谁创建                    | 平台为什么需要它                                                                     |
| ---------------------------------------- | --------------------------- | ------------------------------------------------------------------------------------ |
| 管理 API 令牌                            | 你，在 Cloudflare           | 让 CLI 能创建 zone、修改 DNS、配置 Access。                                          |
| 运行时 API 令牌                          | 你，在 Cloudflare           | 作为 Worker secret 存储，这样关掉终端后平台仍能部署应用。                            |
| PostgreSQL URL                           | 你，配合数据库提供方        | 存放平台的用户、项目与部署。                                                         |
| 登录提供方的 client ID 与 secret         | 你，或使用 Access 登录时由 Void 创建 | 供用户登录平台。                                                            |
| R2 Access Key ID 与 Secret Access Key    | 你，在 Cloudflare           | 让平台能签发上传链接，使 `void deploy` 把静态文件直传 R2。                           |
| Access setup 与 app-access 令牌          | 你，在 Cloudflare           | 仅在使用 Cloudflare Access 时需要：创建与管理 Access 应用。                          |
| JWT 签名密钥                             | Void，在交互式安装时        | 签署平台登录令牌。                                                                   |
| 项目加密密钥                             | Void，在交互式安装时        | 加密你的平台所保存的应用 secret。                                                    |
| 邮件签名密钥                             | Void，在启用邮件时          | 签署确认链接与邮件请求。                                                             |

## Cloudflare API 令牌

按安装器给出的[令牌创建链接](https://developers.cloudflare.com/fundamentals/api/get-started/create-token/)创建一个运行时令牌。当 Void 要创建 zone、添加通配 DNS 或配置 Access 时，它还会另要一个管理令牌。这些链接会选好权限，并根据你的平台名建议名称。

对于域名安装，在 Cloudflare 的表单里选择 zone 范围：

- **已有 zone：** 把 **All Domains** 改为 **Specified Domains** 并选中你的 zone。
- **新 zone：** 两个令牌都保留 **All Domains**。此时 zone 还不存在，而运行时令牌之后需要对它做缓存清除的权限。

把令牌存进密码管理器，再粘贴到掩码的 CLI 提示中。

浏览器登录可以为使用默认 API 主机名的 workers.dev 配置授权。对于已存在 `*.<application domain>` 代理记录的域名安装，它同样有效。如果 Void 读不到账户的 Access 要求，它会另要一个受限范围的 Access 令牌。

配置 Access 需要管理令牌，在 workers.dev 上也一样。受保护的应用，以及 Default-Deny 之下的公开应用，还需要一个长期可用的应用管理令牌，Void 会加密保存它。在你添加域名之前可以先跳过 zone 权限。

浏览器登录不会授予 AI Gateway 访问权限。请在运行时令牌上包含 **Account → AI Gateway → Edit**，这样 Void 才能校验并创建该资源。

管理令牌用于让你的 CLI 安装并维护平台；运行时令牌作为 Worker secret 存储，以便你关闭终端后平台仍能部署应用。它们是两份不同的凭据。

把每个令牌的表单与下面的权限清单逐项对照。安装器会把你在提示处输入的管理令牌存入本次安装加密的本地 checkpoint，并在 resume 时复用。升级、修复以及其他生命周期维护也会用这个已保存的管理令牌。安装过程中若某个令牌被拒绝，可以在提示处换一个新的。显式的 `CLOUDFLARE_API_TOKEN` 或 `CF_API_TOKEN` 优先级更高。密码管理器里的那份副本要留作维护或换机器时使用；脚本通过 `CLOUDFLARE_API_TOKEN` 提供它。

<Callout type="info" title="每个令牌需要选择的权限">

下面是核心平台所需的权限。Cloudflare 在不同令牌页面上可能把写权限标为 **Edit** 或 **Write**，参见它的[权限参考](https://developers.cloudflare.com/fundamentals/api/reference/permissions/)。

| 范围    | 权限                 | 管理令牌 | 运行时令牌                            |
| ------- | -------------------- | -------- | ------------------------------------- |
| Account | Account Settings     | Read     | Read                                  |
| Account | Workers Scripts      | Edit     | Edit                                  |
| Account | Workers Tail         | Read     | Read                                  |
| Account | D1                   | Edit     | Edit                                  |
| Account | Workers KV Storage   | Edit     | Edit                                  |
| Account | Workers R2 Storage   | Edit     | Edit                                  |
| Account | Queues               | Edit     | Edit                                  |
| Account | Hyperdrive           | Write    | Write                                 |
| Account | Account Analytics    | Read     | Read                                  |
| Account | AI Gateway           | Edit     | 使用浏览器登录安装时为 Edit           |
| Account | Containers           | —        | Edit                                  |
| Account | Cloudchamber         | —        | Edit                                  |
| Zone    | Zone                 | Read     | —                                     |
| Zone    | DNS                  | Edit     | —                                     |
| Zone    | Workers Routes       | Edit     | —                                     |
| Zone    | Cache Purge          | —        | Purge                                 |

当 Void 在安装所在的账户里配置 Access 时，最初的管理令牌链接还会选中 **Account → Access: Apps and Policies → Edit** 与 **Account → Access: Organizations, Identity Providers, and Groups → Read**。开启保护后会加上 **Account → Access: Service Tokens → Edit**。当认证配置或已保存的 setup 选择的是已有应用时，该链接会请求 Read 而不是 Edit。这些权限属于管理令牌；运行时令牌不需要它们。

如果你让 Void 创建 zone，管理令牌还需要具备创建 zone 权限的 **Zone Edit**。若 zone 已存在，就用选中的 zone，配 Zone Read 与 DNS Edit。嵌套的应用域名还额外要求管理令牌具备 **SSL and Certificates: Read**。启用了[项目自定义域名](/docs/platform/installation/domains)的安装，要求运行时令牌具备 **SSL and Certificates: Edit**。

Void 会在开通资源之前先检查访问权限。如果它报告缺少某项权限，请针对选定的账户或 zone 更新令牌权限后重试。

</Callout>

## 启用邮件

选择一个共享发信域名以及它所在的 Cloudflare zone ID。邮件 zone 可以与应用 zone 不同，但它必须属于平台所在的 Cloudflare 账户。

在启用平台邮件之前，先为共享发信域名配置 [Cloudflare Email Routing](https://developers.cloudflare.com/email-service/get-started/route-emails/)。如果是子域名，请在 **Email Routing → Settings → Subdomains** 下添加它。让 Cloudflare 添加所需的 MX 与 SPF 记录，然后确认该域名的 MX 记录已指向 Cloudflare。

启用邮件后，管理员可以[为项目注册邮件域名](/docs/platform/administration/email)，项目也能通过运行时令牌注册投递地址。运行时令牌需要这些权限：

| 范围    | 权限                    | 访问级别 |
| ------- | ----------------------- | -------- |
| Account | Email Routing Addresses | Edit     |
| Account | Email Sending           | Edit     |
| Zone    | Zone                    | Read     |
| Zone    | Zone Settings           | Edit     |
| Zone    | Email Routing Rules     | Edit     |

zone 权限必须包含每个要承载邮件的 zone，包括邮件 zone。要向任意收件人发信，Email Sending 的开通需要 Workers Paid。

对于新安装，在运行 `void platform install` 之前设置 `VOID_EMAIL_SENDER_DOMAIN` 与 `VOID_EMAIL_SHARED_ZONE_ID`。这样运行时令牌链接就会预先选好这些权限。

对于已有安装，在 Cloudflare 里编辑它运行时令牌的权限，或用 `VOID_PLATFORM_RUNTIME_CLOUDFLARE_API_TOKEN` 提供一个新的替代令牌。然后运行：

```sh
VOID_EMAIL_SENDER_DOMAIN=mail.example.com \
VOID_EMAIL_SHARED_ZONE_ID=your-zone-id \
void platform upgrade your-installation-id
```

Void 会保存这个域名与 zone 供后续升级使用。请在安装之初就为整个安装周期选定它们。

如果 setup 报告缺少权限，把它加到运行时令牌上并重跑该命令。请勾选表中全部权限，包括 Edit 访问级别与 Email Sending。

从另一台机器维护平台时，把 `VOID_PLATFORM_RUNTIME_CLOUDFLARE_API_TOKEN` 设为当前的运行时令牌，这样 CLI 会校验它的权限。

安装器会配置 email gateway 与共享邮件路由。如果 setup 失败，请修复所报出的权限、DNS 或路由问题后重跑该命令。用 `void platform install --resume --name <installation-id>` 恢复一次全新的安装。

## R2 上传凭据

`void deploy --platform void` 会把应用的静态文件直传 R2，而不经过平台 API。API 用一对 R2 密钥为这些文件签发短时效的上传链接。

安装器会打开 **R2 token creation** 表单，令牌名基于你的平台显示名，并预先选中 **Object Read & Write** 与 **Apply to all buckets in this account (including newly created buckets)**。核对设置后创建一个账户令牌；如果你的角色要求，也可以创建用户令牌。把它的 **Access Key ID** 与 **Secret Access Key** 存进密码管理器，然后两者都粘贴给安装器。它们与管理令牌、运行时令牌是不同的凭据。参见 [R2 的令牌说明](https://developers.cloudflare.com/r2/api/tokens/)。

## 签名与加密密钥

**JWT 签名密钥**用于签署平台登录令牌。**项目加密密钥**用于加密你的平台保存的应用 secret。交互式安装会生成这两把密钥，并把它们保存在本机的加密恢复数据里；本机的生命周期命令就从那里读取它们。

如果想自己留存一份，例如要从 CI 或另一台机器修复平台，请在安装前先生成两把密钥，并设置 `VOID_PLATFORM_JWT_SECRET` 与 `VOID_PLATFORM_PROJECT_SECRET_KEY`。非交互式安装必须同时设置这两项。把下面的命令跑两遍，为两者各生成一把独立密钥：

```sh
openssl rand -base64 32
```

把每个结果都存进密码管理器。该命令生成 32 个随机字节并以 base64 编码，两个字段都适用。原始的这两把密钥要为恢复而保留；在 resume 或升级时不要重新生成。

<Callout type="info" title="生成密钥但不打印到终端">

在 macOS 上，这条命令会把一个合适的随机值复制到剪贴板：

```sh
openssl rand -base64 32 | pbcopy
```

把它以 **JWT signing key** 为名粘贴进密码管理器。再跑一遍命令，把第二个值以 **Project encryption key** 为名保存。在 PowerShell 上用 `Set-Clipboard` 代替 `pbcopy`。如果没有可用的 OpenSSL，就用你的密钥管理器的安全生成器产生 32 个随机字节的 base64，或者 `node -e 'process.stdout.write(require("node:crypto").randomBytes(32).toString("base64"))'`。

</Callout>

启用邮件后，Void 还会为确认链接与服务间的邮件请求创建一把独立的 **邮件签名密钥**。安装器把它保存在加密的恢复状态里。当你需要一份由外部保管的副本时——包括本地恢复文件不会保留的无人值守安装——请把 `VOID_PLATFORM_EMAIL_SIGNING_SECRET` 设为另一个至少 32 个随机字节的值。
