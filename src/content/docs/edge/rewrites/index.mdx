---
title: Rewrites
description: 在另一个 URL 上服务某个路由，同时不改变浏览器地址栏中的地址。
---

Rewrite 让一个路由在另一个 URL 上被服务，而浏览器地址栏保持不变。例如 `/docs` 可以服务 `/en/docs`。如果希望浏览器真正跳转到目标地址，请改用[重定向](/docs/edge/redirects)。

在 [`void.config.ts`](/docs/config) 中定义 rewrite：

```ts title="void.config.ts"
import { defineConfig } from 'void/config';

export default defineConfig({
  routing: {
    rewrites: {
      '/': '/en',
      '/docs': '/en/docs',
      '/docs/*': '/en/docs/:splat',
    },
  },
});
```

对 `/docs/getting-started` 的请求会服务 `/en/docs/getting-started`。其他语言版本，例如 `/ja/docs/getting-started`，仍然走它们自己的路由。

## 规则

- 来源与目标都以 `/` 开头，目标必须是应用内部的路径。
- `*` 匹配任意字符，包括 `/`。目标里用 `:splat` 引用匹配到的那段。
- 第一条命中的规则生效。请把具体的模式写在 catch-all 模式之前。
- Rewrite 在静态资源与应用路由之前执行。

## 中间件中的编程式 rewrite

当目标取决于请求本身时（例如从 cookie 里选出语言版本），请使用 `c.rewrite()`：

```ts
import { defineMiddleware } from 'void';

export default defineMiddleware(async (c, next) => {
  if (c.req.path.match(/^\/(en|ja)(\/|$)/)) return next();

  const locale = detectLocale(c.req);
  return c.rewrite(`/${locale}${c.req.path}`);
});
```

请返回 `c.rewrite()` 的结果。中间件会在目标地址上再次运行，所以要跳过那些已经被 rewrite 过的路径，避免死循环。对于只应发生一次的工作，可以用 `c.isRewritten()` 跳过：

```ts
if (c.isRewritten()) return next();
```

在任何需要权限校验的目标地址上，请保留相应的访问检查。

不带 `?` 的目标会保留请求带来的查询串：`c.rewrite('/search')` 保留 `?q=...`，而 `c.rewrite('/search?q=all')` 会把它替换掉。

编辑器会通过 [`RewriteDestination`](/docs/reference/api/rewrites) 提示已知路由。开启 [`routing.typedRoutes`](/docs/config) 后，不匹配任何路由的字符串会被拒绝。对于运行时拼出来的路径，请从 `void/routes` 导入 `RouteUrl` 并做断言，例如 `` c.rewrite(`/en${c.req.path}` as RouteUrl) ``。

### 运行时 rewrite 到不了静态资源

`c.rewrite()` 面向的是应用路由。要在另一个 URL 上服务 `/hero.png` 这类资源，请改用 `routing.rewrites` 或一条 `_redirects` 规则。若中间件 rewrite 到可识别的资源后缀，会抛出 `VoidAssetRewriteError`。

## 访问原始 URL

`c.originalUrl()` 返回静态 rewrite 或中间件 rewrite 之前被请求的 URL；没有发生 rewrite 时返回 `null`。可以用它生成 canonical 链接或判断语言版本：

```ts
import { defineHandler } from 'void';

export default defineHandler((c) => {
  const original = c.originalUrl();
  return c.json({ pathname: original?.pathname ?? c.req.path });
});
```

## Fallback

`routing.fallbacks` 使用与 rewrite 相同的模式，但只在没有任何资源或路由匹配时生效：

```ts title="void.config.ts"
import { defineConfig } from 'void/config';

export default defineConfig({
  routing: {
    fallbacks: { '/*': '/index.html' },
  },
});
```

客户端路由或默认语言版本的 catch-all 适合用 fallback。Void 路由主动返回的 `404` 仍然是 `404`。对于第三方框架，fallback 还可以替换框架自身的 `404` 响应。

SPA 应用本来就会 fallback 到 `/index.html`。自定义的 fallback 规则先执行，未匹配的路径仍然使用 SPA 外壳，因此你不需要自己再加一条 `'/*': '/index.html'`。

## `_redirects` 文件

你也可以把这些规则放在 Vite 的 `publicDir`（默认是 `public/`）里：

```text
# Fallback：仅在没有任何资源或路由匹配时
/*         /index.html     200

# Rewrite：在资源与路由之前
/docs/*    /en/docs/:splat  200!
```

该文件同样可以包含 [3xx 重定向](/docs/edge/redirects)。`void.config.ts` 中的规则优先于文件里的规则；在每一组内部，第一条命中的生效。

## 客户端导航

Rewrite 在服务端执行。在 Pages 模式下，客户端的 `<Link href="/docs">` 导航可能去取 `/docs` 的 loader 数据，而不是 rewrite 后的路由 `/en/docs`。

当目标的 loader 不同时，请使用 `<a href="/docs">` 发起完整的服务端请求。如果 URL 本身应当改变，请使用重定向。

## 带 rewrite 的 ISR 缓存键

请清理目标路径，例如 `/en/docs/foo`，以清除被 rewrite 的缓存条目，参见[缓存键与 rewrite](/docs/edge/revalidation)。

## 用 `X-Void-Routing` 调试

在开发环境下，打开浏览器 Network 面板查看 `X-Void-Routing` 响应头，它会告诉你命中了哪条规则、以及规则声明在哪里：

```text
X-Void-Routing: rewrite[/docs/*] -> /en/docs/:splat (void.config.ts#routing.rewrites)
X-Void-Routing: c.rewrite -> /new-path (middleware)
X-Void-Routing: pass-through
```
