## 类型管道

- **数据库类型**来自你的 [Drizzle schema](/docs/database)，列类型在编译期就是已知的。
- **路由处理器**：返回类型与校验器 schema 会生成 `RouteMap`，类型化 fetch 客户端消费它。
- **页面 loader**：返回类型通过 `InferProps` 流入页面组件作为 props。
- **页面 action**：校验器 schema 流入 `useForm` 与 `action()`，提供带类型的数据、错误与 URL 自动补全。
- **URL 与导航**：路由模式来自文件名（`[id]`、`[...slug]`），`routeUrl()`、`Link`、`useParams()` 与 `c.redirect()` 都在这些模式上做检查。

所有生成的类型都位于 `.void/`，并在源文件或 schema 变化时自动更新。

## 数据库 → 处理器 → 客户端

类型从 Drizzle schema 经由处理器流向客户端，全程无需手写标注：

```ts title="routes/api/users.ts"
export const GET = defineHandler(async (c) => {
  return db.select({ name: users.name, email: users.email }).from(users);
  // ↑ 返回类型由 schema 列推断
});

export const POST = defineHandler.withValidator({
  body: insertUserSchema, // ← 派生自 Drizzle schema
})(async (c, { body }) => {
  return db.insert(users).values(body).returning();
});
```

```ts
// 客户端：类型由上面的处理器推断
const users = await fetch('/api/users');
//    ^ { name: string; email: string }[]

await fetch('/api/users', {
  method: 'POST',
  body: { name: 'Alice', email: 'alice@example.com' }, // ← 由校验器提供类型
});
```

Drizzle schema 一次定义了数据库列、运行时校验、处理器输入类型与客户端类型检查。对于不对应任何表的端点，使用任意 [Standard Schema](https://standardschema.dev) 库即可。

## Loader → 页面 Props

在页面模式中，loader 的返回类型通过 `InferProps` 流入页面组件：

```ts title="pages/users/index.server.ts"
export type Props = InferProps<typeof loader>;

export const loader = defineHandler(async (c) => {
  return { users: await db.select().from(users) };
});
```

```vue title="pages/users/index.vue"
<script setup lang="ts">
import type { Props } from './index.server';

const { users } = defineProps<Props>();
// ← { users: { id: number; name: string; ... }[] }
</script>
```

不需要手写 interface，props 会与 loader 的返回值始终保持同步。

## Action → useForm

当页面 action 使用 `withValidator()` 时，body schema 会一路流入 `useForm`，为你带来带类型的数据、带类型的错误键与 URL 自动补全：

```ts title="pages/users/create.server.ts"
export const action = defineHandler.withValidator({
  body: insertUserSchema,
})(async (c, { body }) => {
  await db.insert(users).values(body);
});
```

```ts
const form = useForm('/users/create', { name: '', email: '' });
// ^ 自动补全 ^ 必须匹配 body schema

form.errors.email; // ✓ string | undefined
form.errors.foo; // ✗ TypeScript 报错
```

具名 action 的工作方式完全相同。`?actionName` 后缀会选择该 action 对应的类型：

```ts
const updateForm = useForm('/users/[id]?update', { name: '' }, { params: { id } });
const deleteForm = useForm('/users/[id]?delete', { id: '' }, { params: { id } });
// 每个表单的 data 与 errors 都由各自的校验器提供类型
```

`action()` 辅助函数获得同样的类型检查。

## 类型化 URL 与导航

路由模式使用与文件名相同的方括号：`pages/users/[id].tsx`、`.vue` 或 `.svelte` 对应 `/users/[id]`。同一套模式可用于类型化 `fetch()`、WebSocket 的 `connect()`、页面 action 与 `useParams()`。

### routeUrl() 与目标对象

```ts
import { routeUrl } from 'void/routes';

const url = routeUrl('/users/[id]', {
  params: { id: 42 },
  query: { tab: 'activity' },
  hash: 'details',
});
// /users/42?tab=activity#details
```

TypeScript 会检查路由是否存在以及必需的参数名。参数值可以是字符串或数字，会被自动做 URL 编码；query 值支持字符串、数字、布尔与数组，数组展开为重复键，`null` 与 `undefined` 被省略。

返回的字符串可以交给 `Link`、普通 `<a>` 或 `c.redirect()`。程序化导航与 `c.rewrite()` 也可以直接接受目标对象，检查与编码方式和 `routeUrl()` 一致：

```ts
import type { RouteDestination } from 'void/routes';

const profile = {
  pathname: '/users/[id]',
  params: { id: 42 },
  query: { tab: 'activity' },
  hash: 'details',
} satisfies RouteDestination;
```

catch-all 页面（如 `pages/files/[...path].tsx`）把整段路径作为一个值传入；未命名的 catch-all（`[...]`）把值放在 `'*'` 键下：

```ts
routeUrl('/files/[...path]', { params: { path: 'docs/get started' } });
// /files/docs/get%20started

routeUrl('/files/[...]', { params: { '*': 'docs/get started' } });
```

`void/routes` 为这些字符串导出两个类型：

- `RouteUrl`：某条路由的 URL。`routeUrl()` 返回它，`c.rewrite()`、`useIslandForm()` 与 `revalidate({ paths })` 接受它，`routing.prerender` 列表可以用它标注。
- `Href`：链接或 `c.redirect()` 能指向的一切：`RouteUrl`、同页的 query 或 hash，以及外部 URL。

### 页面参数

把页面的路由模式作为类型参数传给 `useParams()`，即可得到带类型的参数：

```tsx
import { useParams } from '@void/react';

const { id } = useParams<'/users/[id]'>(); // id: string
useParams<'/users/[id]'>().idd; // ✗ 没有这个参数
useParams<'/userz/[id]'>(); // ✗ 没有匹配的页面
```

类型参数只决定推断结果，不改变读取的是哪个页面；不传时 `useParams()` 返回 `Record<string, string>`。要用页面模式，而不是 HTTP 或 WebSocket 路由：命名 catch-all（`/files/[...path]`）返回 `{ path: string }`，未命名 catch-all 没有具名参数。

服务端 `c.req.param('slug')` 接受任意名字。把结果通过 `PageParams` 读取，拼写或缺失的参数名就会变成类型错误：

```ts
import type { PageParams } from 'void/routes';

const { slug } = c.req.param() as PageParams<'/posts/[slug]'>;
```

### 预渲染路径

给 `getPrerenderPaths()` 标注 `PageParams`，可以检查每个路径都带上页面必需的参数：

```ts title="pages/blog/[slug].server.ts"
import type { PageParams } from 'void/routes';

export async function getPrerenderPaths(): Promise<PageParams<'/blog/[slug]'>[]> {
  return [{ slug: 'hello-world' }];
}
```

Void 不会从文件名推断这个返回类型，需要显式标注才能发现缺失或拼错的键。自定义 SSR 返回的是完整路径，类型为 `Promise<string[]>`。

在 `void.config.ts` 中，`routing.prerender` 可以用 `satisfies RouteUrl[]` 检查路径（需启用 `routing.typedRoutes`）：

```ts title="void.config.ts"
import { defineConfig } from 'void/config';
import type { RouteUrl } from 'void/routes';

export default defineConfig({
  routing: { prerender: ['/', '/blog/hello-world'] satisfies RouteUrl[] },
});
```

### 检查 URL 字符串

启用 `routing.typedRoutes` 后，链接、router 调用、重定向、rewrite、缓存重验证、岛屿表单与流客户端里的 URL 字符串都会与你的路由比对，错拼的 URL 在编译期就会报错。用 `void init` 创建的项目已经默认开启；已有项目在配置中加入：

```ts title="void.config.ts"
import { defineConfig } from 'void/config';

export default defineConfig({
  routing: { typedRoutes: true },
});
```

此后字符串必须匹配某一条路由，末尾可以跟 query 或 hash：

```tsx
import { Link } from '@void/react';
import { routeUrl } from 'void/routes';

<Link href="/about">关于</Link>
<Link href={`/users/${user.id}?tab=activity`}>资料页</Link>
<Link href={routeUrl('/users/[id]', { params: { id } })}>资料页</Link>
<Link href="/abuot">关于</Link> // ✗ 没有匹配的路由
```

链接同时接受同页的 query 与 hash（`?page=2`、`#comments`），以及 `http://`、`https://`、`mailto:`、`tel:` URL。站内路径要写绝对路径，`../settings` 这类相对路径会被拒绝；静态段可以用原文（`/café menu`）或大写百分号编码（`/caf%C3%A9%20menu`）。

只能由根级动态路由（`/[slug]`、`/[...slug]`、`/[...]`）处理的 URL 必须改用 `routeUrl()`，例如 `routeUrl('/[...slug]', { params: { slug: 'dashboard' } })`；其他已声明路由仍然接受被检查的字符串。自定义 404 页面请使用 `_not-found`。

字符串检查依赖 TypeScript 的模板字符串类型，它不会校验单个动态段的取值：`/users/[id]` 同样接受 `/users/` 与 `/users/42/edit`。因此优先用 `routeUrl()` 编码参数，并在运行时校验不可信的 URL。

SSE 与 live 流客户端接受路由 URL 与外部 `http://` / `https://` URL；同页链接、`mailto:`、`tel:`、`ws://` 不是有效的流目标。

`c.redirect()` 接受与链接相同的字符串，外加 `URL` 与目标对象。来自 SDK、CMS 或 `public/` 的 URL 可以用 `as Href` 跳过检查：

```ts
import { routeUrl, type Href } from 'void/routes';

c.redirect('/about');
c.redirect(routeUrl('/users/[id]', { params: { id } }));
c.redirect({ pathname: '/users/[id]', params: { id } });
c.redirect('https://example.com/login');
c.redirect(new URL('https://example.com/login'));
c.redirect(dynamic as Href);
```

只对确实可信的 URL 做断言。`?redirectTo=` 这类请求值必须先校验再重定向。

运行时才确定、但你会自己校验的值，用这两个类型标注：

```tsx
<Link href={post.path as RouteUrl}>{post.title}</Link>
<Link href={user.website as Href}>网站</Link>
```

dev server 会保持路由类型最新。修改 `routing.typedRoutes` 后需要重启它，或运行 `void prepare`。

## 哪些内容会被检查

| 层次                | 被类型检查的内容                                                                                                                                            |
| ------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 数据库              | 来自 Drizzle schema 的表列、值类型、insert / update 结构                                                                                                    |
| 处理器              | `c.env` 绑定、校验器输入、返回类型                                                                                                                          |
| fetch 客户端        | 路由路径、HTTP 方法、body / query / params、响应类型                                                                                                        |
| 导航                | `routeUrl()` 与目标对象中的路由模式、必需参数名与参数值                                                                                                     |
| 链接                | 启用 `routing.typedRoutes` 后，`Link`、router 方法、`c.rewrite()`、`useIslandForm()`、SSE 与 live 流客户端中的 URL 字符串                                   |
| `c.redirect`        | 启用 `routing.typedRoutes` 后，路由 URL、同页 query 与 hash、目标对象、`URL` 值，以及 `http(s)` / `mailto:` / `tel:` 字面量；无法检查的字符串需要 `as Href` |
| `useParams`         | 页面模式，以及该模式返回的参数名                                                                                                                            |
| `c.req.param`       | 结果标注为 `PageParams` 时的页面参数名                                                                                                                      |
| `getPrerenderPaths` | 返回类型标注为 `PageParams` 时的页面参数名                                                                                                                  |
| `revalidate`        | 启用 `routing.typedRoutes` 后，`paths` 中的 URL 字符串                                                                                                      |
| `routing.prerender` | 数组标注为 `satisfies RouteUrl[]` 时的路径                                                                                                                  |
| `useForm`           | action URL、数据字段、错误键、`reset()` 参数（含 `{ initial: true }`）、params、`resetOnSuccess`                                                            |
| `action()`          | action URL、数据负载、params                                                                                                                                |

## 序列化

类型化 fetch 客户端推断的是 JSON 转换之后的类型：服务端的 `Date` 在客户端是 `string`，数组与 tuple 内部同样如此。

| 源类型或值                            | 客户端类型或行为                             |
| ------------------------------------- | -------------------------------------------- |
| `string`、`number`、`boolean`、`null` | 不变                                         |
| `Date`                                | `string`                                     |
| 数组与 tuple                          | 逐个转换元素，保留 tuple 的位置与 `readonly` |
| 数组中的 `undefined`、函数、symbol    | `null`                                       |
| 对象值为 `undefined`、函数、symbol    | 该属性被省略                                 |
| symbol 键                             | 被省略                                       |
| `Response`                            | 从推断的 JSON 类型中排除，运行时原样透传     |
| `bigint`                              | JSON 不支持                                  |

值可能被省略的属性在客户端类型中变为可选：处理器返回 `{ label: string | undefined }`，客户端得到 `{ label?: string }`。

页面 [loader](/docs/pages-routing) 会保留更丰富的值，包括 `Date`、`Map`、`Set` 与 `bigint`；直接从 loader 返回 props，就能在页面组件中保持这些类型。

## 上下文变量

中间件与处理器通过 Hono 的上下文变量共享带类型的数据。扩展 `CloudContextVariables` 来定义你自己的变量：

```ts title="middleware/01.auth.ts"
declare module 'void' {
  interface CloudContextVariables {
    requestId: string;
  }
}

export default defineMiddleware(async (c, next) => {
  c.set('requestId', crypto.randomUUID());
  await next();
});
```

此后在任何地方 `c.get("requestId")` 都返回 `string`，无需类型断言。来自多个文件的多次扩展会被合并。

## 自定义绑定类型

对于 Cloudflare 原生部署，把绑定声明在 `void.config.ts` 中即可获得 `c.env` 上的类型。例如添加一个限流器：

```ts title="void.config.ts"
import { defineConfig } from 'void/config';

export default defineConfig({
  cloudflare: {
    ratelimits: [
      { name: 'MY_RATE_LIMITER', namespace_id: '1001', simple: { limit: 10, period: 60 } },
    ],
  },
});
```

运行 `void prepare` 或启动 dev server 之后，就能不带类型断言地使用它：

```ts
import { defineHandler } from 'void';

export const GET = defineHandler(async (c) => {
  const { success } = await c.env.MY_RATE_LIMITER.limit({ key: 'example' });
  return { success };
});
```

Service binding 使用 `Fetcher`，Durable Object 使用 `DurableObjectNamespace`，其他绑定使用各自的标准 Cloudflare 类型。对于 RPC 方法等更专门的类型，在 tsconfig 覆盖的文件里扩展 `CloudBindings`：

```ts
import type {} from 'void';

declare module 'void' {
  interface CloudBindings {
    AUTH: Fetcher & { check(): Promise<boolean> };
  }
}
```

扩展既可以细化生成的绑定，也可以补充你自己另外提供的绑定。`env.ts` 中声明的值仍保留其 schema 类型。这些类型作用于 Void 的 `c.env`；使用 `cloudflare:workers` 时请采用框架自己的绑定类型。

## 配置

在项目中扩展生成的 tsconfig：

```json title="tsconfig.json"
{
  "extends": "./.void/tsconfig.json",
  "compilerOptions": {
    "target": "ES2022",
    "module": "ES2022",
    "moduleResolution": "bundler",
    "strict": true,
    "jsx": "react-jsx",
    "types": ["void/env"]
  },
  "include": ["src", "routes", "middleware", "crons", "queues"]
}
```

如果你已经有 TypeScript 配置，运行 `void init --tsconfig` 可以在保留现有设置的前提下加入 Void 类型。

<Callout type="tip" title="在 CI 中生成类型">
  在 CI 中或全新克隆之后运行 `void prepare`，或者让 `vite dev` / `vite build` 在正常的应用流程中生成
  `.void/` 文件。
</Callout>
