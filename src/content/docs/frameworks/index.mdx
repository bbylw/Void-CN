import Callout from '@/components/docs/Callout.astro';

保留你框架自己的路由与渲染，把数据库、存储、定时任务与部署交给 Void。本节的各篇指南说明如何把每个框架接到 Void 上。

在框架的 Vite 配置里加上 `voidPlugin()`：它会检测资源使用、生成数据库类型、管理迁移，并为 `void deploy` 准备好应用。

TanStack Start 与 React Router 使用 Void 提供的 Cloudflare Vite 插件；SvelteKit、Nuxt、Analog 与 Astro 则使用各自的 Cloudflare 适配器。接入方式不同，但路由与渲染始终由框架负责。

## 识别方式

| 框架                                              | 通过哪个依赖识别        | 集成方式                                         |
| ------------------------------------------------- | ----------------------- | ------------------------------------------------ |
| [TanStack Start](/docs/frameworks/tanstack-start) | `@tanstack/react-start` | Vite 插件组合，`voidPlugin()` 与框架插件并列运行 |
| [React Router v7](/docs/frameworks/react-router)  | `@react-router/dev`     | Vite 插件组合，接入方式与 TanStack Start 相同    |
| [SvelteKit](/docs/frameworks/sveltekit)           | `@sveltejs/kit`         | 基于 Vite，使用它自己的 Cloudflare 适配器        |
| [Nuxt](/docs/frameworks/nuxt)                     | `nuxt`                  | 使用它自己的 CLI 与构建工具链                    |
| [Analog](/docs/frameworks/analog)                 | `@analogjs/platform`    | 基于 Vite，使用 Nitro 加 Cloudflare preset       |
| [Astro **v7+**](/docs/frameworks/astro)           | `astro`                 | 使用它自己的 CLI 与 Cloudflare 适配器（要求 v7） |

识别是自动的：CLI 会读取你 `package.json` 里的依赖。

把 `voidPlugin()` 加进框架的 Vite 配置即可获得全部能力：

```ts
import { defineConfig } from 'vite';
import { voidPlugin } from 'void';

export default defineConfig({
  plugins: [voidPlugin()],
});
```

<Callout type="info" title="vinext 的中间件与静态文件">
  在 vinext 应用中，`middleware.ts` 与 `proxy.ts` 同样作用于 `public/`
  中的文件。存在任一文件时，静态请求也会经过 Worker
  并计入其请求用量；没有中间件的应用保持静态资源直出。
</Callout>

## 能力与限制

| 能力                                       | 框架模式                                  |
| ------------------------------------------ | ----------------------------------------- |
| 绑定推断（D1、KV、R2、队列、AI…）          | 支持                                      |
| 带类型的数据库代码生成与查询               | 支持                                      |
| 迁移管理（`void db generate` / `migrate`） | 支持                                      |
| 定时任务与队列                             | 支持                                      |
| 环境变量（`void/env` 校验值）              | TanStack Start、React Router、vinext 支持 |
| 缓存与路由规则                             | 支持                                      |
| 部署（Cloudflare 与 Void 平台）            | 支持                                      |
| 页面模式（loaders / actions）              | 不适用，由框架负责                        |
| Void 托管的认证                            | 不支持                                    |

在框架的 Vite 配置里加上 `voidPlugin()` 之后，框架应用就能获得与 [Void 应用](/docs/app-types) 基本一致的后端与平台能力：

- **绑定推断：** 从源码中检测 D1、KV、R2、AI 与队列。
- **带类型的数据库：** 查询类型来自你的 Drizzle schema。
- **迁移：** 开发启动时更新本地 D1，迁移在 `void deploy` 时被校验并部署。
- **运行时辅助函数：** `void/db`、`void/kv`、`void/storage` 与 `void/ai` 在开发和生产中提供带类型的 Cloudflare 绑定访问。
- **环境变量：** TanStack Start、React Router 与 vinext 支持 [`void/env`](#环境变量) 校验过的值。
- **认证：** 框架模式暂不支持 Void 托管的认证，目前请使用 Better Auth 针对你框架的官方集成。
- **定时任务：** 通过 `crons/` 目录提供 scheduled 处理器。
- **队列消费者：** 通过 `queues/` 目录提供带类型的生产者与消费者。
- **再验证与预渲染：** 在 `void.config.ts` 中用 [`routing.revalidate`](/docs/edge/revalidation) 与 [`routing.prerender`](/docs/edge/prerendering) 配置；Void 应用还可以在配套的 `.server.ts` 文件里按页面设置。

对框架应用，无论是 `void deploy` 还是 `void deploy --platform cloudflare`，Void 的再验证只缓存公开的 HTML 文档响应；客户端的数据请求仍按框架自己的行为处理。带 `Set-Cookie` 的响应，以及 `Cache-Control` 为 `private`、`no-store` 或 `no-cache` 的响应，绝不会被共享。

框架也可以按各自的方式直接访问绑定：SvelteKit 3、Analog 与 Astro 用 `cloudflare:workers` 的 `env`，SvelteKit 2 用 `platform.env`，Nuxt 用 `event.context.cloudflare.env`。

<Callout type="warn" title="认证">
  框架模式下不支持 Void 托管的认证。请使用 Better Auth 针对你的框架的官方集成。
</Callout>

## 配置

### 环境变量

在 TanStack Start、React Router 与 vinext 中，可以从 `void/env` 导入 `env`，读取由 `env.ts` schema 校验的值：默认值、类型转换与异步校验器在开发与生产中都生效。读取缺失或非法的值会抛出错误，但未读取该值的请求不受影响。其他框架请使用框架自己的环境变量 API。

### `void.config.ts`

多数配置都由 Void 自动推断。需要覆盖默认值或微调行为时，使用 `void.config.ts`：

```ts
import { defineConfig } from 'void/config';

export default defineConfig({
  inference: {
    build: 'nuxt build',
    scanDirs: ['src', 'server', 'lib'],
    bindings: { db: 'MY_DB' },
  },
  routing: {
    prerender: ['/', '/about', '/pricing'],
    revalidate: 60,
  },
});
```

| 字段                 | 用途                                                                                                                                                              |
| -------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `inference.build`    | 覆盖默认的构建命令                                                                                                                                                |
| `inference.scanDirs` | 绑定推断要扫描的目录（默认值因框架而异）                                                                                                                          |
| `routing.prerender`  | 部署时预渲染为静态 HTML 的路径                                                                                                                                    |
| `routing.revalidate` | 被缓存响应的默认再验证 TTL（秒）                                                                                                                                  |
| `inference.bindings` | 覆盖推断出的绑定。仅当自动检测不符合预期时才需要它，取值 `true` 或自定义绑定名，例如 `"db": "MY_DB"`。                                                            |
| `routing.notFound`   | **会被忽略。** SvelteKit、Nuxt、Analog 与 Astro 会把 `not_found_handling` 固定为 `"none"`——未匹配的 HTML 由框架 Worker 负责。设置了它，`void deploy` 会给出警告。 |

完整参考见[配置](/docs/config)。

### Cloudflare 设置

使用 Cloudflare 开发运行时的框架，需要把适配器指向 Void 生成的 `.void-wrangler.jsonc`，各框架的接入指南会列出对应的适配器选项。你的 Cloudflare 设置写在 `void.config.ts` 里：

```ts
import { defineConfig } from 'void/config';

export default defineConfig({
  cloudflare: {
    name: 'my-app',
    compatibility_date: '2026-02-24',
    compatibility_flags: ['nodejs_compat'],
  },
});
```

已有的绑定会被保留。D1、KV 与 R2 在部署之前使用本地占位 ID。对于直接连到 Cloudflare 的项目，导入 `void/ai` 会在开发期间加上一个远端 Workers AI 绑定，要使用它需要先完成 [Cloudflare 登录](/docs/ai)；直接部署同样会包含推断出的 AI 绑定。

Void 会把这些设置与推断出的绑定合并，并把开通的资源 ID 记录在 `void.lock.json` 中，两个文件都要提交。

## 部署

运行 `void deploy` 会用你的框架构建，并部署到所选目标。环境配置与 CI 参见[部署](/docs/deployment)。

## TanStack Start

由 `@tanstack/react-start` 识别。在 TanStack Start 的 Vite 插件之后加入 `voidPlugin()`：

```ts title="vite.config.ts"
import { defineConfig } from 'vite';
import { voidPlugin } from 'void';
import tsConfigPaths from 'vite-tsconfig-paths';

export default defineConfig({
  plugins: [tsConfigPaths(), voidPlugin()],
});
```

完整接入步骤参见 [TanStack Start](/docs/frameworks/tanstack-start)。

## React Router v7

由 `@react-router/dev` 识别。把 `voidPlugin()` 加进 React Router 的 Vite 配置：

```ts title="vite.config.ts"
import { reactRouter } from '@react-router/dev/vite';
import tailwindcss from '@tailwindcss/vite';
import { defineConfig } from 'vite';
import { voidPlugin } from 'void';

export default defineConfig({
  plugins: [tailwindcss(), voidPlugin(), reactRouter()],
});
```

完整接入步骤参见 [React Router v7](/docs/frameworks/react-router)。

## SvelteKit

由 `@sveltejs/kit` 识别。SvelteKit 2 在本地开发期间不支持 `cloudflare:workers` 导入，请使用 `void/db` 或框架自己的绑定访问 API；SvelteKit 3 支持这些导入。

完整接入步骤参见 [SvelteKit](/docs/frameworks/sveltekit)。

## Nuxt

由 `nuxt` 识别。同样需要注意本地开发期间 `cloudflare:workers` 导入的限制，请使用 `void/db` 或框架的绑定访问 API。

完整接入步骤参见 [Nuxt](/docs/frameworks/nuxt)。

## Analog

由 `@analogjs/platform` 识别。把 `voidPlugin()` 加进它的 Vite 配置即可获得绑定推断与迁移管理。

完整接入步骤参见 [Analog](/docs/frameworks/analog)。

## Astro

由 `astro` 识别，需要 Astro v7+。Astro 的 `vite.plugins` 配置支持 `voidPlugin()`：

```ts title="astro.config.mjs"
import { defineConfig } from 'astro/config';
import { voidPlugin } from 'void';

export default defineConfig({
  vite: {
    plugins: [voidPlugin()],
  },
});
```

完整接入步骤参见 [Astro](/docs/frameworks/astro)。

  本站本身就是一个使用 Astro + MDX + Tailwind CSS 构建的静态站点，
  可以作为结构组织的参考，但它并不使用 Void 作为运行时。
</Callout>

## Hono

Hono 不是元框架，而是 Void 路由层的底层。你可以直接使用 Hono 的生态包，任何 `hono/*` 内置中间件或第三方包都能工作：

```ts
import { defineHandler } from 'void';
import { cors } from 'hono/cors';

export const GET = defineHandler(cors({ origin: 'https://app.example.com' }), (c) => ({
  ok: true,
}));
```

使用前请在应用中自行安装 `hono`：`npm install hono`。更多细节参见 [Hono](/docs/integrations/hono)。
