<Callout type="warn" title="仅限 Void 应用">
  带类型的 WebSocket 路由目前仅在原生 Void 应用中可用，元框架模式下尚未提供。
</Callout>

每个路由实例拥有自己的 Cloudflare Durable Object 用于共享状态，WebSocket 路由需要 Cloudflare 部署目标。例如 `/rooms/[id]` 会为每个聊天室分配一个独立实例，可用于聊天、在线状态、协同文档或通知。

## 路由文件

在 `routes/` 中使用 `.ws.ts`、`.ws.tsx`、`.ws.js`、`.ws.jsx`、`.ws.mts` 或 `.ws.mjs` 后缀创建 WebSocket 路由：

```text title="routes/"
├── chat/
│   └── [room].ws.ts
└── notifications.ws.ts
```

处理器里含 JSX（例如渲染要发给客户端的 HTML 片段）时用 `.ws.tsx` 或 `.ws.jsx`，JSX runtime 与[服务端路由](/docs/server-routing)一致。

文件命名规则与常规[服务端路由](/docs/server-routing#路由文件)一致：

- `index.ws.ts` 变为父级路径
- `[id].ws.ts` 增加一个动态 `[id]` 段
- `[...slug].ws.ts` 变为 catch-all
- 路由组如 `(marketing)/chat.ws.ts` 不出现在 URL 中
- `chat.dev.ws.ts` / `chat.prod.ws.ts` 把路由限制在某个环境

<Callout type="info" title="环境后缀的位置">
  环境后缀放在 `.ws` **之前**，即 `chat.dev.ws.ts`。`chat.ws.dev.ts` 不会被识别。
</Callout>

## defineRoom

当客户端应当共享一个由路由标识的房间或文档时，使用 `defineRoom()`：

```ts title="routes/chat/[room].ws.ts"
import * as v from 'valibot';
import { defineRoom } from 'void/ws';

const ClientMessage = v.variant('type', [
  v.object({ type: v.literal('chat.message'), text: v.string() }),
]);

const ServerMessage = v.variant('type', [
  v.object({
    type: v.literal('chat.message'),
    id: v.string(),
    text: v.string(),
    userId: v.string(),
  }),
  v.object({ type: v.literal('chat.joined'), userId: v.string() }),
]);

export default defineRoom({
  messages: {
    client: ClientMessage,
    server: ServerMessage,
  },
});
```

消息 schema 使用 [Standard Schema](https://standardschema.dev) 校验器编写，因此可以用 Valibot、Zod 或 ArkType。客户端与服务端的方向都有完整类型，非法消息在到达你的处理器之前就会被拒绝。

<Callout type="tip">
  每个房间背后都是一个由 SQLite 支持的 Durable Object。房间内的共享状态可以使用
  [`defineDurableState`](/docs/durable-state) 中相同的模式定义。
</Callout>

## 服务端 action

房间可以声明一组具名 `actions`，让其他服务端代码带类型地调用它们。action 在房间自己的 Durable Object 内运行，因此可以主动关闭连接或广播，而不必等客户端发来一帧消息。

```ts title="routes/relay/[accountId].ws.ts"
import * as v from 'valibot';
import { getSession } from 'void/auth';
import { defineRoom } from 'void/ws';

const ClientMessage = v.object({ type: v.literal('relay.ping') });
const ServerMessage = v.object({ type: v.literal('relay.message'), text: v.string() });

export default defineRoom({
  messages: { client: ClientMessage, server: ServerMessage },
  onConnect(ctx) {
    // id 来自已认证的会话，绝不来自客户端输入
    const session = getSession()?.session;
    if (session) {
      ctx.connection.setState({ sessionId: session.id });
    }
  },
  actions: {
    async revokeSession(ctx, sessionId: string, code: number) {
      let closed = 0;
      for (const connection of ctx.room.getConnections()) {
        const state = connection.state as { sessionId?: string } | undefined;
        if (state?.sessionId !== sessionId) continue;
        connection.close(code, 'session revoked');
        closed += 1;
      }
      return { closed };
    },
    async announce(ctx, text: string) {
      await ctx.room.broadcast({ type: 'relay.message', text });
    },
  },
});
```

在路由处理器、auth hook、队列消费者或 cron 任务里，用 `void/ws/server` 的 `getRoom()` 调用 action：

```ts
import { getRoom } from 'void/ws/server';

// Better Auth 的 databaseHooks.session.delete.after，或任意其他服务端代码
const room = getRoom('/relay/[accountId]', { params: { accountId } });
const { closed } = await room.actions.revokeSession(session.id, 4001);
```

`getRoom()` 定位的就是 `connect()` 会连上的同一个实例：传同样的路由模式与同样的 params，自定义 `key` 也会生效。它读取当前运行时的 env，因此在 Void 运行的任何处理器里都可用；在处理器之外调用时，把你手上已有的 bindings 对象传进去：`getRoom('/relay/[accountId]', { params: { accountId }, env: bindings })`。

<Callout type="warn" title="只用服务端可信的状态匹配连接">
  从 URL、查询串或客户端消息里读到的 session id 可以是客户端任意发送的值，据此撤销会关错
  socket。请从 `getSession()` 或你自己的记录里取 id，在 `onConnect`
  中存进连接状态，再由撤销会话的代码传入同一个 id。会话被撤销时想立刻关闭闲置的 socket，就声明一个
  room action 并从撤销处调用它。
</Callout>

- 每个 action 参数都要写类型标注：入参与返回值由定义推导，未标注的参数是 `never`。
- action 拿到 `ctx.id`、`ctx.params`、`ctx.env`、`ctx.storage` 与 `ctx.room`，没有 `ctx.request` 也没有 `ctx.user`：调用方是你的服务端代码，授权判断要在发起调用的地方做。
- 在 action 里 `ctx.room.broadcast()` 与连接的 `send()` 可以发任意事件，但服务端消息 schema 仍会在运行时校验。
- 参数要跨越 Durable Object 边界，只能传 structured-clone 可序列化的数据，不要传回调或类实例。
- 未知的 action 名或 handler 报错会让这次调用被 reject；未知路由、`defineWebSocket()` 路由或缺少参数则在联系任何 Durable Object 之前直接抛错。
- 不要在同一个房间自己的 hook 里调用它的 action——那里直接用 `ctx.room`，从房间内部发起的调用会等待房间自身。

action 不是端点。它们通过 Durable Object RPC 从你的 Worker 发起，浏览器请求或 WebSocket 消息都无法调用。
