---
title: 项目协作
description: 邀请读者、协作者与项目管理员加入托管项目。直接部署到 Cloudflare 的项目仍是单人使用。
---

托管在 Void 平台上的项目可以有一个所有者，外加读者、协作者和项目管理员。团队访问是平台能力；直接部署到 Cloudflare 的项目不支持。

## 角色

| 角色       | 权限                                                                                                                    |
| ---------- | ----------------------------------------------------------------------------------------------------------------------- |
| 读者       | 查看项目、用量、资源、部署、构建、日志与成员名册。不能部署。                                                            |
| 协作者     | 拥有读者权限，另外可以部署、回滚、取消、执行迁移、管理密钥与数据库配置，以及处理部署前置条件。                          |
| 项目管理员 | 拥有协作者权限，另外可以管理域名、邮件目的地、GitHub 配置、邀请、角色与移除成员。                                       |
| 所有者     | 拥有项目管理员权限，另外可以删除项目。                                                                                  |

只有所有者能创建、列出、续期或吊销项目的 CI 部署凭据。这些凭据以计费所有者的身份无人值守地执行部署，并且独立于成员的登录会话，因此协作者和项目管理员是用自己的账户部署，而不是铸造一份长期有效的所有者凭据。

所有者的套餐、限制与停用状态决定了整个项目。成员自己的套餐不会改变项目可用的用量，通过协作者操作也绕不开针对所有者的停用。项目管理员并不是安装管理员，也不会获得平台级的访问权限。

## 邀请已注册用户

所有者或项目管理员可以用对方在同一平台现有账户上注册的邮箱地址发出邀请：

```sh
void project team invite teammate@example.com --role collaborator
```

要管理非当前关联的项目，请传入 `--project <slug>`。无法识别的邮箱会被拒绝。项目邀请既不会创建账户，也不会把该地址加入限制注册的白名单。

邀请七天后过期。如果平台无法发送邀请邮件，CLI 会打印邀请 ID 以及连接和接受命令，供你转给被邀请的用户。该用户在同一平台上运行 `void project team pending` 时也会看到这封邀请。

用这些命令列出成员名册和已发出的邀请：

```sh
void project team list
void project team invitations
```

## 响应邀请

按邀请里的地址连上平台，然后查看发给你账户的邀请，并用邀请 ID 响应：

```sh
void connect api.example.com
void project team pending
void project team accept <invitation-id>
# 或者
void project team decline <invitation-id>
```

邀请绑定的是那个已注册的账户。把 ID 转发给别人并不能让他们接受。

这三条命令使用 `void connect` 选定的当前平台连接，即使在某个已关联其他项目、或直接部署到 Cloudflare 的目录里也是如此。设置了 `VOID_API_URL` 时，它以 `VOID_API_URL` 为准。如果你用 `VOID_TOKEN`，请同时把 `VOID_API_URL` 设为对应的平台。每条命令都会显示它连接的平台。

接受邀请只是授予访问权限，并不会关联你当前的目录。请进入被邀请应用的目录，如果它还没关联就运行 `void project link`。如果它已经关联到另一个项目，请另开一份不含 `.void/project.json` 的 checkout，在那里连上被邀请的平台，再运行 `void project link`。

如果找不到邀请，请检查平台与登录的账户。要切换账户，先把 `VOID_API_URL` 设为邀请所属的平台 URL，取消已设置的 `VOID_TOKEN`，然后用被邀请的邮箱地址依次运行 `void account logout` 和 `void account login`。邀请已过期或被吊销，请项目管理员重新邀请你。

## 变更或移除访问权限

所有者和项目管理员可以变更任何非所有者成员，或吊销待处理的邀请：

```sh
void project team role <user-id> reader
void project team remove <user-id>
void project team revoke <invitation-id>
```

非所有者成员可以用 `void project team leave` 退出。所有者不能退出；必须由安装管理员先[转移所有权](/docs/platform/administration/projects)。

当协作者或管理员被移除、退出或改为读者时，平台会替换该项目的 Workers 用于调用平台服务（例如 AI、邮件、远程绑定）的凭据。当项目的所有 Worker 都换上新凭据后，旧凭据即失效，通常大约需要 10 分钟；如果期间正在部署，时间会更长。若替换无法完成，旧凭据会继续有效直到替换成功，所有者和管理员会在 `void project status` 与 `void project team list` 中看到告警。WebSocket 连接会重连一次。某个 Worker 切换到新凭据期间，它调用平台服务可能短暂失败，一次定时任务可能被跳过，队列消息会在几分钟后重新投递。

被移除者此前部署的代码会继续运行，直到你替换它。如果你已不再信任那份代码，请部署你信任的代码；那次部署之后平台会再次替换凭据。为回滚而保留的、他们此前的部署仍使用旧凭据，因此回滚到这些版本后，AI、邮件与 ISR 重新验证会失败，直到你重新部署。
