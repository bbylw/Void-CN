通过 [Cloudflare Hyperdrive](https://developers.cloudflare.com/hyperdrive/) 连接你的 MySQL 数据库，然后用 Drizzle 定义表并查询它们。Void 会为你配置连接，并在部署时应用迁移。

## 配置

在 `void.config.ts` 中设置方言：

```json
{
  "database": "mysql"
}
```

为本地开发添加直连地址：

```dotenv
DATABASE_URL=mysql://user:password@host:3306/app
```

Void 会为 dev server 和 `void db` 命令读取 `.env`。在生产环境，Worker 通过推断出的 `HYPERDRIVE` 绑定连接。

## 定义 schema

```ts title="db/schema.ts"
import { int, mysqlTable, text, timestamp } from 'void/schema-mysql';

export const messages = mysqlTable('messages', {
  id: int('id').autoincrement().primaryKey(),
  text: text('text').notNull(),
  createdAt: timestamp('created_at').notNull().defaultNow(),
});
```

项目使用 MySQL 方言时，`void gen model` 会自动生成 MySQL 的构造器。

## 迁移

使用常规流程：

```sh
void db generate
void db migrate
void deploy
```

直连 Cloudflare 部署时，请在运行 `void deploy --platform cloudflare` 的 shell 中导出生产环境的 `DATABASE_URL`。Void 用它来创建 Hyperdrive，并在上传 Worker 之前应用已签入的待处理迁移；它不会被写入 Worker 配置。

同一时间只有一个迁移过程会改动数据库，无论它来自 `void db migrate`、`void db reset`、`void db seed` 在加载数据前执行的重置、`void deploy --platform cloudflare`，还是任何使用该数据库的项目的 `void deploy`。Better Auth 的表改动也在同一个过程内执行。另一个过程会等待它：用 `DATABASE_URL` 连接的命令最长等待约 20 秒，部署到 Void 平台的 `void deploy` 最长约 2 分钟，之后报错停下并提示你重试。

### 失败的迁移

每个迁移文件都在一个事务里执行，因此只改动数据的文件失败时数据库保持不变。在分片的 Vitess keyspace 上（例如分片的 PlanetScale 数据库），某个分片提交失败并不会撤销已经提交的分片。MySQL 会立即提交 `CREATE TABLE`、`ALTER TABLE` 这类 schema 变更，所以含 schema 变更的文件中途失败时，它之前已执行的语句会保留下来。错误信息会指出失败的文件名。

要恢复，请撤销已经应用的语句，修好该文件，然后再次运行 `void db migrate` 或 `void deploy`：

```sh
void db execute "DROP TABLE comments"
void db execute --remote "DROP TABLE comments" # 已部署的数据库
```

MySQL 不接受在 `ADD COLUMN` 和 `CREATE INDEX` 上使用 `IF NOT EXISTS`，因此撤销一条语句通常比让它可重复执行更简单。迁移越小，需要撤销的东西越少。

## 数据库命令

`void db push`、`generate`、`migrate`、`status`、`reset`、`seed`、`execute`、`studio`、`export`、`rename-migrations` 与 `set-url` 都支持 MySQL。本地命令使用 `.env` 中的 `DATABASE_URL`；`--remote` 执行与 Studio 使用已关联 Void 项目所存储的加密 URL。
