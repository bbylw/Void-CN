import Callout from '@/components/docs/Callout.astro';

用 TypeScript 定义表，再用 `void/db` 导出的 `db` 查询它们。Void 内置了 [Drizzle ORM](https://orm.drizzle.team)，并为你配置好连接，因此同一份 schema 与查询流程可以直接用在 D1、PostgreSQL 或 MySQL 上。

```text title="db/"
├── schema.ts            表定义（唯一真相来源）
├── schema/              拆分 schema 文件（可选）
│   ├── users.ts
│   └── posts.ts
├── migrations/          生成的 SQL 迁移文件
│   ├── 20260410161500_create_users.sql
│   └── 20260410161501_add_posts.sql
├── seed.ts              程序化种子脚本（可选）
└── seed.sql             原始 SQL 种子文件（可选替代）
```

## 选择方言

在 `void init` 期间选择数据库，或在 `void.config.ts` 中设置 `database`：

|          | [D1（SQLite）](/docs/database/d1) | [PostgreSQL](/docs/database/postgresql) | [MySQL](/docs/database/mysql) |
| -------- | --------------------------------- | --------------------------------------- | ----------------------------- |
| 配置     | 默认                              | `"database": "pg"`                      | `"database": "mysql"`         |
| 托管方   | Void                              | 自带数据库                              | 自带数据库                    |
| 连接方式 | 自动的 D1 绑定                    | Hyperdrive                              | Hyperdrive                    |

<Callout type="tip" title="Void 平台会关闭 Hyperdrive 查询缓存">
  这样读取能反映已完成的写入。已有连接会在项目下一次部署时更新。
</Callout>

## 定义 schema

在 `db/schema.ts` 中使用来自 `void/schema-d1`、`void/schema-pg` 或 `void/schema-mysql` 的列辅助函数定义表。

```ts title="db/schema.ts (SQLite / D1)"
import { sql } from 'void/db';
import { sqliteTable, text, integer } from 'void/schema-d1';

export const users = sqliteTable('users', {
  id: integer('id').primaryKey({ autoIncrement: true }),
  name: text('name').notNull(),
  email: text('email').notNull().unique(),
  role: text('role').notNull().default('user'),
  createdAt: text('created_at')
    .notNull()
    .default(sql`(datetime('now'))`),
});
```

```ts title="db/schema.ts (PostgreSQL)"
import { pgTable, serial, text, timestamp } from 'void/schema-pg';

export const users = pgTable('users', {
  id: serial('id').primaryKey(),
  name: text('name').notNull(),
  email: text('email').notNull().unique(),
  role: text('role').notNull().default('user'),
  createdAt: timestamp('created_at').notNull().defaultNow(),
});
```

```ts title="db/schema.ts (MySQL)"
import { int, mysqlTable, text, timestamp } from 'void/schema-mysql';

export const users = mysqlTable('users', {
  id: int('id').autoincrement().primaryKey(),
  name: text('name').notNull(),
  email: text('email').notNull().unique(),
  createdAt: timestamp('created_at').notNull().defaultNow(),
});
```

schema 辅助函数已随 `void` 提供。你可以直接手写表，也可以用 `void gen model` 生成一个起点。

你也可以把 schema 拆分到 `db/schema/` 下的多个文件，并从 barrel 文件重新导出：

```ts title="db/schema/users.ts"
export const users = /* ... */;
```

```ts title="db/schema.ts"
export * from './schema/users';
export * from './schema/posts';
```

### 列名大小写

没有显式命名的列（例如 `createdAt: timestamp()`）默认直接用 key 作为列名。把 `database.casing` 设为 `'snake_case'` 后，这类列会存成 `created_at`。它同时作用于 `void/db` 查询和 `void db generate`、`push`、`seed` 等命令。已经显式命名的列（例如 `text('created_at')`）保持原名。

```ts title="void.config.ts"
import { defineConfig } from 'void/config';

export default defineConfig({
  database: { dialect: 'pg', casing: 'snake_case' },
});
```

```ts title="db/schema.ts"
import { pgTable, serial, text, timestamp } from 'void/schema-pg';

export const posts = pgTable('posts', {
  id: serial().primaryKey(),
  title: text().notNull(),
  createdAt: timestamp().notNull().defaultNow(), // created_at
});
```

D1 项目省略 `dialect` 即可。数据库里已经有表时，改完 `casing` 要运行 `void db generate` 并检查生成的迁移，再决定是否应用。

## 查询

Void 会从 `void/db` 重新导出所有常用的 [Drizzle 查询运算符](https://orm.drizzle.team/docs/select)，因此你不需要单独安装 `drizzle-orm`。从 `void/db` 导入 `db`，从 `@schema` 导入你的表。

<Callout type="info" title="@schema 是什么">
  `@schema` 是 Void 插件自动配置的 Vite 路径别名，指向你的 `db/schema.ts`（或拆分后的
  `db/schema/`）。你直接用它导入表定义即可。
</Callout>

```ts
import { users } from '@schema';
import { db } from 'void/db';

const allUsers = await db.select().from(users);
```

### 筛选

```ts
import { users } from '@schema';
import { db, eq, and, or } from 'void/db';

// 单个条件
const user = await db.select().from(users).where(eq(users.id, 1));

// 多个条件
const admins = await db
  .select()
  .from(users)
  .where(and(eq(users.role, 'admin'), eq(users.name, 'Alice')));

// 或条件
const editors = await db
  .select()
  .from(users)
  .where(or(eq(users.role, 'admin'), eq(users.role, 'editor')));
```

### 插入

```ts
// 单行
await db.insert(users).values({
  name: 'Alice',
  email: 'alice@example.com',
});

// 插入并返回新建的行
const [created] = await db
  .insert(users)
  .values({ name: 'Bob', email: 'bob@example.com' })
  .returning();

// 多行
await db.insert(users).values([
  { name: 'Alice', email: 'alice@example.com' },
  { name: 'Bob', email: 'bob@example.com' },
]);
```

### 更新与删除

```ts
await db.update(users).set({ role: 'admin' }).where(eq(users.id, 1));

const [updated] = await db.update(users).set({ role: 'admin' }).where(eq(users.id, 1)).returning();

await db.delete(users).where(eq(users.id, 1));
```

### 列选择、排序与分页

```ts
import { users } from '@schema';
import { db, desc } from 'void/db';

const names = await db.select({ name: users.name, email: users.email }).from(users);
// names: { name: string; email: string }[]

const page = await db.select().from(users).orderBy(desc(users.createdAt)).limit(10).offset(20);
```

### 类型辅助

`void/db` 也重新导出 Drizzle 类型 `SQL`、`SQLWrapper`、`AnyColumn` 与 `BatchItem`，用来给你的查询辅助函数和批次做标注：

```ts
import { posts } from '@schema';
import { db, sql, type BatchItem, type SQL, type SQLWrapper } from 'void/db';

function contains(column: SQLWrapper, text: string): SQL {
  return sql`instr(${column}, ${text}) > 0`;
}

// 仅 D1：db.batch() 至少接受一个查询
const writes: [BatchItem<'sqlite'>, ...Array<BatchItem<'sqlite'>>] = [
  db.update(posts).set({ published: true }).where(contains(posts.title, 'void')),
];
await db.batch(writes);
```

### 关联

```ts
import { users, posts } from '@schema';
import { db, eq } from 'void/db';

const results = await db
  .select({
    id: posts.id,
    title: posts.title,
    author: users.name,
  })
  .from(posts)
  .innerJoin(users, eq(posts.userId, users.id));
```

如果 schema 中定义了 [relations](https://orm.drizzle.team/docs/relations)，还可以使用 Drizzle 的关系查询 API：

```ts
const usersWithPosts = await db.query.users.findMany({
  with: { posts: true },
});
```

## 种子数据

用 `void db seed` 重置本地数据库、重新应用迁移，然后运行一个种子文件。

用 `db/seed.ts` 做程序化种子，用 `db/seed.sql` 写 SQL。JavaScript 以及 `.mts` / `.mjs` 文件同样可用。如果存在多个种子文件，用 `--file <path>` 选择其中一个。

### 程序化种子

当你想在代码里生成种子数据时，使用 `db/seed.ts`。导出一个默认函数或名为 `seed` 的函数。

```ts title="db/seed.ts"
import { defineSeed } from 'void/seed';

export default defineSeed<typeof import('./schema')>(async ({ db, schema }) => {
  const rows = Array.from({ length: 100 }, (_, i) => ({
    text: `Seed message ${i + 1}`,
  }));

  await db.insert(schema.messages).values(rows);
});
```

种子上下文包含：

- `dialect`：`"sqlite"`、`"postgresql"` 或 `"mysql"`
- `db`：指向本地数据库的 Drizzle 实例
- `schema`：来自 `db/schema.ts` 或 `db/schema/` 的导出

### SQL 种子

如果你更喜欢原始 SQL，可以继续用 `db/seed.sql`：

```sql title="db/seed.sql"
INSERT INTO messages (text) VALUES ('Hello from SQL');
```

## 从 schema 派生校验器

用 `void/drizzle-zod`、`void/drizzle-valibot` 或 `void/drizzle-arktype` 从表中派生请求校验器。在表定义之后添加它：

```ts title="db/schema.ts"
import { createInsertSchema } from 'void/drizzle-zod';

export const insertUserSchema = createInsertSchema(users, {
  name: (schema) => schema.min(1),
  email: (schema) => schema.email(),
});
```

```ts
import { pipe, minLength, email } from 'valibot';
import { createInsertSchema } from 'void/drizzle-valibot';

export const insertUserSchema = createInsertSchema(users, {
  name: (schema) => pipe(schema, minLength(1)),
  email: (schema) => pipe(schema, email()),
});
```

```ts
import { type } from 'arktype';
import { createInsertSchema } from 'void/drizzle-arktype';

export const insertUserSchema = createInsertSchema(users, {
  name: type('string > 0'),
  email: type('string.email'),
});
```

`createInsertSchema` 会生成与 `$inferInsert` 匹配的校验器：有默认值或自增的列变为可选，`NOT NULL` 列保持必填。可选的第二个参数让你逐列细化，既可以传入一个接收生成 schema 的回调，也可以直接传入一个类型来覆盖某个字段。

在[路由处理器](/docs/server-routing)中用 `withValidator()` 使用派生的 schema：

```ts title="routes/api/users/index.ts"
import { users, insertUserSchema } from '@schema';
import { defineHandler } from 'void';
import { db } from 'void/db';

export const POST = defineHandler.withValidator({
  body: insertUserSchema,
})(async (c, { body }) => {
  const [created] = await db.insert(users).values(body).returning();
  return created;
});
```

三个可用函数：

| 函数                 | 用途                                             |
| -------------------- | ------------------------------------------------ |
| `createInsertSchema` | 校验插入数据，排除自动生成的列并应用默认值       |
| `createSelectSchema` | 匹配查询结果行的结构                             |
| `createUpdateSchema` | 与 insert 类似，但所有字段都是可选的（部分更新） |

Void 已经打包了 Drizzle 适配器。如果你在 schema 文件中直接使用校验库自身的 API，请自行安装它：

```bash
npm install zod
# or
npm install valibot
# or
npm install arktype
```

## CLI 命令

| 命令               | 用途                                   |
| ------------------ | -------------------------------------- |
| `void db push`     | 在本地应用 schema 变更，不生成迁移文件 |
| `void db generate` | 生成 SQL 迁移                          |
| `void db migrate`  | 在本地应用待处理的迁移                 |
| `void db status`   | 检查 schema 漂移与待处理迁移           |
| `void db seed`     | 重置本地数据库并运行种子文件           |
| `void db execute`  | 对本地或 `--remote` 数据库执行临时 SQL |
| `void db restore`  | 回档直连 Cloudflare 部署的 D1 数据库   |

`void db execute` 会为每条有返回行的语句打印结果表格，纯改动数据的语句不打印内容；包含多条语句的 SQL 作为脚本执行，不打印结果行。直连 Cloudflare 的 D1 部署上，超过 100 KB 的 `--file` 会走 D1 import：等待期间数据库不服务查询，也不打印结果行。`DELETE`、`UPDATE`、`DROP` 这类破坏性语句在 TTY 下会先要求确认，`--yes` 可跳过，非 TTY（CI）不会询问。

连接配置、SQL 执行、Studio、导出等更多命令见 [CLI 参考](/docs/reference/cli/database)。

## 接管已有的 Drizzle PostgreSQL 数据库

要让 Void 接管一个已经由 Drizzle 迁移过的 PostgreSQL 数据库，必须在首次部署之前把它已应用的迁移记录下来。每个数据库都要各做一遍，development 与 production 的历史可能不同；接管完成后保留 Drizzle 的历史表，后续迁移一律交给 Void。

1. 备份数据库并暂停部署，先在一个恢复出来的副本上演练整个流程。
2. 在 `void.config.ts` 中设置 `database: 'pg'`。保留现有的 schema、SQL 文件名与 `db/migrations/meta/` 目录，接管期间不要重新生成或重命名迁移。
3. 读取 Drizzle 的迁移历史。默认表是 `drizzle.__drizzle_migrations`，若你配置了别的 schema 或表名就换成自己的：

   ```sql
   SELECT hash, created_at FROM drizzle.__drizzle_migrations ORDER BY created_at;
   ```

   把每行的 `created_at` 对上 `meta/_journal.json` 里的 `when`，`hash` 对上对应 SQL 文件的 SHA-256。有差异先解决完再继续。

4. 把下面这段存成 `adopt-void.sql`，`VALUES` 中只填**你已核实确实应用过**的文件名（含 `.sql`），待处理的迁移不要写进去：

   ```sql title="adopt-void.sql"
   BEGIN;
   CREATE TABLE IF NOT EXISTS _void_migrations (
     name TEXT PRIMARY KEY,
     applied_at TEXT NOT NULL
   );
   INSERT INTO _void_migrations (name, applied_at)
   VALUES
     ('0000_create_users.sql', CURRENT_TIMESTAMP::text),
     ('0001_add_email.sql', CURRENT_TIMESTAMP::text)
   ON CONFLICT (name) DO NOTHING;
   COMMIT;
   ```

5. 用你的 PostgreSQL 客户端执行这个文件，遇错即停，并使用 Void 将要使用的数据库与 search path。它只记录文件名，既不会重跑其中的 SQL，也不改动 Drizzle 的历史。
6. 让 Void 连上该数据库，然后运行 `void db status`，应当只有新增的迁移是待处理状态。直连 Cloudflare 部署时，在执行 `void deploy` 的 shell 或 CI 环境里设置 `DATABASE_URL`。

## 手写迁移

部署时，Void 会把 Drizzle schema 与 `db/migrations/meta/` 中的快照做比较。如果你有 SQL 迁移却没有这份元数据，运行 `void db generate` 会为同样的表再创建一个迁移。

要保留已有的迁移历史：

1. 让你的 Drizzle schema 与 SQL 迁移所创建的表保持一致。
2. 在项目的一份临时副本中删除 `db/migrations/`，然后运行 `void db generate`。
3. 把生成的 `meta/` 目录复制回你原来的迁移目录。在 `_journal.json` 中，按顺序为每个已有的 SQL 文件替换 `entries` 条目：`idx` 从 `0` 开始连续递增，`tag` 为去掉 `.sql` 的文件名，`when` 使用递增的时间戳，`version` 沿用生成条目的值。`breakpoints` 设为该文件是否使用了 `--> statement-breakpoint` 行。
4. 把生成的快照重命名为 `<prefix>_snapshot.json`，其中 `<prefix>` 是最后一个迁移 tag 在第一个 `_` 之前的部分。例如 `001_create_users.sql` 对应 `001_snapshot.json`。

检查并提交这份元数据，然后再次运行 `void deploy`。如果还没有任何数据库应用过这些 SQL，你也可以直接用 `void db generate` 生成的迁移替换它们。

<Callout type="warn" title="statement-breakpoint">
  对于包含触发器的 D1 迁移，以及包含触发器、存储过程、函数或事件的 MySQL 迁移，请在每个完整 SQL
  语句之后添加一行 `--> statement-breakpoint`，包括触发器结尾的 `END;`。保持触发器主体完整。
</Callout>

## 脚手架

`void gen model` 会生成适配当前方言的 `sqliteTable`、`pgTable` 或 `mysqlTable` 定义：

```bash
void gen model posts title:string body:text published:boolean
```

它会创建：

1. `db/schema/posts.ts`：包含 `id`、`createdAt`、`updatedAt` 与你指定列的 Drizzle 表定义
2. 更新 `db/schema.ts`，加入 `export * from "./schema/posts"`
3. `routes/api/posts/index.ts`：列表 GET 与带校验的插入 POST
4. `routes/api/posts/[id].ts`：按 id 查询的 GET，带 404 处理

完整生成器列表见 [CLI 参考](/docs/reference/cli/generate)。

## 迁移出问题时回档

在自有 Cloudflare 账户上部署 D1 时，`void deploy` 会在应用迁移之前保存一个恢复点，并打印出对应的 `void db restore` 命令。遇到坏迁移时：

1. 如果线上版本依赖新的 schema，先用 `void project rollback` 回退代码。
2. 用打印出的 bookmark 执行 `void db restore`；也可以传 `--timestamp`，值必须是带时区的 ISO 8601 时间，例如 `2026-10-16T09:30:00Z`。
3. 修正或删掉失败的迁移之后再部署。恢复点同时会回退迁移历史，所以下一次部署会重新应用待处理的迁移文件。

`void db restore` 只作用于直连 Cloudflare 部署的 D1（基于 Time Travel），需要单次指定目标时给它加 `--platform cloudflare`。

<Callout type="warn" title="恢复会丢弃之后的写入">
  回档会丢弃所选时间点之后的所有写入，Time Travel 的历史也有限：Workers Free 保留 7 天，Workers Paid
  保留 30 天；更早的迁移只能用一个新的迁移反向修正。Void
  执行前会要求确认，并打印一条可撤销本次恢复的命令；脚本与 CI 用
  `--yes`。恢复之后请确认已部署的代码能与恢复到的 schema 配合。
</Callout>

## D1 的特别说明

本页保留 D1 最常踩坑的部分；本地数据库、批量操作与完整的副本一致性配方见 [D1（SQLite）](/docs/database/d1)。

### 读副本需要显式开启

D1 read replication 现在改为 opt-in，在 `void.config.ts` 里设置后运行 `void deploy`：

```ts title="void.config.ts"
import { defineConfig } from 'void/config';

export default defineConfig({
  database: { readReplication: true },
});
```

新建数据库默认不带副本。省略 `readReplication` 时，部署不会改动数据库已有的副本设置——也就是说要关掉已有副本，必须显式写 `false` 再部署，光升级版本或删掉这个选项都没用。开启后，`void/db` 的 `db` 会为每个 Void 请求使用一个 D1 session，读取可以在靠近请求的位置执行，且同一请求中后续的查询能看到至少相同的数据。没有 Void 请求作用域的框架处理器会让每个数据库操作从主库开始；`createDb` 则为你传入的绑定开启一个可用副本的 session。

<Callout type="warn" title="旧部署可能已经带副本">
  Void 0.21.3 曾自动开启 D1
  读副本，用该版本或其后的版本部署过的项目可能已经有副本，而副本会在请求之间提供陈旧数据。请升级到支持
  `database.readReplication` 的版本（自托管的平台也要一起升级），把它设为 `false`
  后重新部署。平台无法应用这个设置时，`void deploy` 会在上传任何东西之前报错停下。
</Callout>

### 用 primary-first session 避开陈旧读

认证会话检查始终从主库开始，因此被撤销的会话不会因为副本延迟而被接受。其他必须拿到最新主库数据的读取，在请求内新建一个客户端：

```ts
import { users } from '@schema';
import { env } from 'cloudflare:workers';
import { defineHandler } from 'void';
import { createDb } from 'void/db';

export const GET = defineHandler(async () => {
  const primaryDb = createDb(env.DB, { session: 'first-primary' });
  return primaryDb.select().from(users).all();
});
```

`session: 'first-primary'` 让第一个查询走主库，后续查询看到至少相同的数据。默认值 `'first-unconstrained'` 允许第一个查询使用副本。

### 用 bookmark 在后续请求里看到自己的写入

保存之后要在下一个请求读到它，就在请求之间携带 [D1 bookmark](https://developers.cloudflare.com/d1/best-practices/read-replication/#start-a-session-from-previous-context-bookmark)：它让 D1 只能使用至少已追平你先前观察到的数据库状态的副本。bookmark 只适用于签发它的那个数据库，不同数据库与环境要用不同的 cookie 名或存储 key，切换数据库时清掉已存的 bookmark（清除即开启一条新的一致性链）。把它当作不透明字符串，不要解析或自行构造。

用 `void/db` 的 `setSession()` 在处理器或 Pages loader 之前设定默认 `db` 的 session，处理完再取回要返回给客户端的 bookmark：

```ts title="middleware/01.database.ts"
import { getCookie, setCookie } from 'hono/cookie';
import { defineMiddleware } from 'void';
import { getBookmark, setSession } from 'void/db';

export default defineMiddleware(async (c, next) => {
  const path = c.req.path;
  if (path !== '/profile' && !path.startsWith('/profile/')) {
    await next();
    return;
  }

  const incoming = getCookie(c, 'db-bookmark');
  setSession(incoming === undefined ? 'first-unconstrained' : { bookmark: incoming });
  await next();

  const bookmark = getBookmark();
  if (bookmark) {
    setCookie(c, 'db-bookmark', bookmark, {
      httpOnly: true,
      secure: new URL(c.req.url).protocol === 'https:',
      sameSite: 'Lax',
      path: '/',
    });
  }
  c.header('Cache-Control', 'private, no-store');
});
```

- 把参与一致性链的路径限定在你真正需要的一组页面上，其余路由保持原有缓存策略；同时给这些响应加上 `Cache-Control: private, no-store`。
- bookmark 约束的是数据库查询，不是缓存的响应。参与的页面要关闭 ISR（在页面的 `.server.ts` 里 `export const revalidate = 0`）并绕过已有的响应缓存——只设响应头不足以绕过 ISR 命中。
- 一致性关键的数据库操作要在处理器或 loader 返回前 await；中间件取 bookmark 之后才完成的延后查询不保证被反映进去。
- 并发的响应可能用较旧的 bookmark 覆盖 cookie。纯 API 场景可改用 `X-DB-Bookmark` 请求/响应头，并在浏览器端用 Web Locks 只保留较大的那一个——同一数据库的 bookmark 可按字典序排序，较旧的响应不能覆盖较新的值。
- 本地通过 `void/client` 发起的 server-side 请求共享同一个 session：`'first-unconstrained'` 会保留已满足的要求，中间件重跑也不会重置数据库进度。要做独立的主库优先读取或在使用 `db` 之后取更新的 bookmark，请改用 `createDb`。

其他 D1 绑定或框架自己的端点（例如 Astro API 路由）没有 Void 的请求作用域，用 `createDb(binding, { session })` 建立客户端，查询后把 `getBookmark(client)` 写回响应头：

```ts
import { users } from '@schema';
import { createDb, getBookmark } from 'void/db';

export async function readUsers(request: Request, binding: D1Database) {
  const incoming = request.headers.get('X-DB-Bookmark');
  const client = createDb(binding, {
    session: incoming === null ? 'first-unconstrained' : { bookmark: incoming },
  });
  const result = await client.select().from(users).all();

  const headers = new Headers({ 'Cache-Control': 'private, no-store' });
  const bookmark = getBookmark(client);
  if (bookmark) headers.set('X-DB-Bookmark', bookmark);
  return Response.json(result, { headers });
}
```

裸的 D1 绑定始终从主库读取；其他查询库与原生 D1 调用要各自调用 `withSession()` 才会用到副本。用 `cloudflare:workers` 中的 `env.DB` 可以配合其他查询库或原生 D1 API：

```ts title="Kysely"
import { env } from 'cloudflare:workers';
import { Kysely } from 'kysely';
import { D1Dialect } from 'kysely-d1';

const db = new Kysely<Database>({ dialect: new D1Dialect({ database: env.DB }) });
```

```ts title="原生 D1"
import { env } from 'cloudflare:workers';

const { results } = await env.DB.prepare('SELECT * FROM users WHERE id = ?').bind(userId).all();
```

无论使用哪种查询层，Void 仍然处理绑定推断与部署。

  Nuxt 与 SvelteKit 2 在本地开发期间不支持 `cloudflare:workers` 导入。请改用 `void/db`
  或框架自己的绑定访问 API。SvelteKit 3 支持这些导入。
</Callout>
