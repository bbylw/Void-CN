`void init` 在项目初始化过程中就会把编程智能体一并配置好：

```sh
npx void init
```

新项目会得到一份精简的 `AGENTS.md`，说明 Void 是什么、文档到哪里读。

在已有项目中，Void 在创建、追加或更新 `AGENTS.md` 之前都会先征求你的同意，并保留 Void 段落之外你自己的指令；选择拒绝时文件保持原样。CI 与非交互式运行不会改动已有项目的指令文件。

完整的 Markdown 文档随包发布在 `node_modules/void/docs/`，入口是 `guide/quickstart.md`（上手）与 `reference/cli.md`（命令）。即使没有链接技能，智能体也可以直接读取这些文件。

## AGENTS.md

在**新建**项目中，初始化流程会写入一份精简的 `AGENTS.md`，其中包含 Void 的关键约定：

- 项目结构：`routes/`、`pages/`、`db/`、`middleware/`、`crons/`、`queues/`、`env.ts`
- 类型约定：不要手写接口，类型从 Drizzle schema 与处理器推断
- 资源约定：导入即启用，不要手写 `wrangler.jsonc`
- 命令约定：`void db generate`、`void deploy`、`void env check`

在**已有**项目中，Void 不会直接覆盖你的指令文件，它会先征求你的同意，再进行合并或替换；`AGENTS.md` 里 Void 段落以外的内容会被保留。

## 打包的技能

技能（skill）把智能体指向完成当前任务所需的命令与文档。它们链接到已安装的 `void` 包，因此指引始终与你应用实际使用的版本一致。

Void 提供两个技能：

- **`void`：** 应用开发用到的命令与文档。
- **`migrate-vite-cloudflare-to-void`：** 把现有 `@cloudflare/vite-plugin` 应用迁移到 Void 的技能。

当 `void init` 检测到受支持智能体的配置时，会自动链接这些技能。例如 Claude Code 使用 `.claude/skills/`，Codex 使用 `.agents/skills/`。技能读取应用已安装的文档，所以指引与该项目的 Void 版本相符；全局安装的技能在没有本地安装时，会使用自己所在 `void` 包里的文档。如果一个智能体都没检测到，指令文件仍然会直接指向随包发布的文档。

<Callout type="tip">
  如果你使用的智能体不在自动检测范围内，可以手动指向随 `void` 包一起提供的 Markdown 指南与参考，位于
  `node_modules/void/docs/`。
</Callout>

## 离线文档

`void` 包自带完整的 Markdown 指南与参考：

```text title="node_modules/void/docs/"
├── guide/      指南（从 quickstart.md 开始）
└── reference/  参考（命令见 cli.md）
```

这让你可以在没有网络访问的环境中，也能让智能体查到准确的 API 与 CLI 用法。

## 对智能体友好的 API 设计

Void 的很多设计本身就是为了让编程智能体更容易写对：

| 设计                 | 原因                                       |
| -------------------- | ------------------------------------------ |
| 文件即路由           | 智能体不需要维护一份路由表，只需创建文件   |
| 类型从 schema 推断   | 不需要手写 DTO，编译错误会指出不一致的地方 |
| 导入即启用资源       | 不需要生成或维护基础设施配置               |
| `void init` 写入约定 | 智能体第一次打开项目就知道规则             |

## 给智能体的建议

在仓库的 `AGENTS.md` 中写清楚以下内容，可以显著提升智能体的产出质量：

1. 项目使用的数据库方言（D1 / PostgreSQL / MySQL）与表结构约定
2. 页面采用服务端渲染还是客户端渲染（是否导出 `ssr = false`）
3. 认证方案与 `trustedOrigins` 的范围
4. 部署目标（Cloudflare 直连还是团队平台）
5. 提交前需要运行的检查：`void db generate`、`void env check`、`bun run build`
